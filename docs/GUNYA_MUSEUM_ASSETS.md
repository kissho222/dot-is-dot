# ぐにゃぐにゃ怪盗：博物館チュートリアル 3D制作仕様（v1.0）

## 目的と作品の趣旨
『ぐにゃぐにゃ怪盗』の**チュートリアルを実際に組み立てて試すための3D素材一式**をdotへ委任する。操作系・戦闘・敵AI・完全なギミックを一気に実装するのでなく、Blenderで編集可能なモデルとUnityで組み立てられるシーン用部品を揃える。

ゲームは一本道を通常より高速（構想値2〜3倍程度）で自動走行し、プレイヤーがスロー中に身体をぐにゃぐにゃに変形させて障害物を回避し、クリア後に通常速度で一連の動作を見る。**基本前進を止めず、必ずしも窓からの脱出やルート変更を必要としない**。

## 制作単位と依存関係

### A. 博物館ステージ・ループ廊下
- 博物館らしい床・壁・天井・柱・照明・展示台・展示室への入口などの**モジュール部品**を揃える。
- **周回できる（途切れず一周して元の位置につながる）廊下**を作る。直線・コーナー・接続部分を分離して、再配置・延長できる。
- ゲームの前進ルートは常時一定速度で進められるよう、曲がり角などでコリジョンに引っかかったりキャラクターが立ち止まったりしないルート形状にする。
- Unity側のSpline/Waypoints等の走行ルートに合わせやすい**通路中央のガイド・開始点・一周接続点の目安**を準備。最初の段階では実際の走行制御は作らない。
- **赤外線レーザー障害物**の発光ラインと発射／受光ユニットの3Dモデルを制作。複数の高さ・角度・交差配置ができるよう分割し、回避チュートリアル向けの配置例を提示する。
- レーザーはUnityで見やすいマテリアル／LineRendererなどの表現を前提にする。赤外線は通常肉眼では見えないため、**ゲームとして見える赤い警備レーザー**という演出表現で制作。物理ダメージ・感知・ゲームオーバー処理は別タスク。

### B. ダイヤモンドと取り外せる立方体ガラスケース
- 宝石らしいカットを持つ**ダイヤモンドの3Dモデル**と、独立した展示台を制作。
- ダイヤモンドを囲む**立方体状のガラスケース**を作る。**下面は開放（底板なし）し、上・前後・左右の5面で箱状の覆い**になる。
- ガラスケースは展示台／ダイヤモンドから**独立Object**にし、**上方向へ持ち上げて取り外せる構造**。ダイヤモンドと接着・結合してはならない。
- 本作のギャグ：**ダイヤモンドではなく、ダイヤモンドを覆うガラスケースを盗む**。ガラスケースの持ち上げ後もダイヤモンドが展示台に残る構図をチェックする。
- 透明材質で内部のダイヤが見えること。ガラスの厚み・縁・反射をゲームでわかる程度に作り、透過ソートやモバイル性能等への配慮が必要。過剰な屈折は不要。
- ケースの持ち上げ・持ち運び・物理は将来のゲーム実装。まずは手動で上下移動でき、取り外した状態を表示できればよい。

### C. 警備員・警棒・拳銃
- 展示施設の**警備員（人型NPC）1体**。制服等の外観を持ち、走行路沿いに配置しやすい一般的な体型・アニメ適性で制作する。
- **警棒（baton）1点、拳銃（handgun）1点**をゲーム内の装備小物として制作。実在銃器の内部機構・実射撃機能や製造可能な精密構造は不要。形状は架空の簡略化したゲーム用プロップとする。
- 警棒と拳銃は独立Objectで、警備員の手に持たせる／外すことを想定して原点・大きさ・グリップ位置を整理する。
- 警備員モデルには基本的なボーン／ウェイトを備え、立ち姿・警棒を持つ・拳銃を持つなどの**姿勢見本**を出せるとよい。ただしAI／攻撃ロジック／弾丸／ヒット判定／アニメ完成は対象外。
- 背景群衆や多数の警備員バリエーションは現段階では不要。

## 共通の実装・納品ルール
- **見た目＋将来拡張できる部品構造**を優先。制御プログラムは依頼外。
- 各モデルを個別の編集可能な `.blend` 等で保持、Unity用に `.fbx` 等を出力できるようにする。マテリアル／テクスチャは相対パスで取りまとめる。
- ループ廊下、レーザー、ガラスケース、ダイヤモンド、展示台、警備員、警棒、拳銃をそれぞれ識別できる命名にする。
- ダイヤモンドとガラスケースが別物であることが最重要。ガラスを上に引き抜いて盗めるよう、上下方向の干渉や展示台との隙間を確認する。
- 廊下全景・コーナー連結・展示室・レーザー回避箇所・ガラスケース装着／取り外し・警備員と装備のプレビューを提出。
- 著作権やライセンス不明の有料モデル等をコピーしない。**独立したオリジナル制作**とする。
- レベルの尺、展示室の順序、カラーリング、美術館の豪華さ、警備員のキャラデザ、レーザー配置数は**初回ラフを見て確定**。勝手に細かな物語や勝利条件を追加しない。
- 制作物は**NEKOLPOS本体のUnity作業環境と分離**し、所有者が並行してCodexを使えるようにする。
- **Codexは個別の許可があるまで起動しない。** dotによる3D制作・制作管理タスクである。

## 手順
1. **レベルの簡易グレーボックス**で廊下のループと展示室を構成。
2. 途中にレーザーの配置ラフを入れ、ゲーム速度を想定して距離感・回避余地をレビュー（詳細な検証は走行システム実装後）。
3. ダイヤ＋上に外せるケース、警備員＋装備を別々に制作。
4. 編集可能な制作ファイルとUnity向けファイルを納品し、プレビューで所有者に確認。
5. 実際にUnityで動作確認した範囲と未実施の範囲を明確にして報告。
