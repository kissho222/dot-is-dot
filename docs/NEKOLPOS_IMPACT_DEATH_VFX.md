# NEKOLPOS：接触・被弾・死亡VFX 品質改善仕様 v1.0
更新：2026-10-19 ／ 対象：dotによる試作・VFXアセット制作

> **目的**：既存の汎用Impact FX 10種を品質改善の素材・構想として扱い、5cmのプレイヤーが巨大な猫「ネルコ」から受ける接触・攻撃・死亡を、分かりやすく、気持ちよく、ゲーム独自の質感で表現する。
>
> **最優先の見せ場**：「予備動作 → 衝撃の瞬間に即時暗転 → 黒背景には赤いエフェクトだけが残る → 消失 → 既存の死亡後／翌朝復活シーケンス」。
>
> **この文書は制作・検証用の仕様**。本編シーンの全面改修や死亡処理の書き換えを許可するものではない。まず独立した検証シーン・Prefabで制作してオーナーにレビューを求める。

## 0. 使用環境・事前確認

- GitHubにあるNEKOLPOSの設定では、ProjectVersionは **Unity 6000.3.10f1**、Packages/manifest.jsonのURPは **17.3.0**、GraphicsSettingsにはCustom Render Pipeline Assetの参照がある（2026-10-19確認）。
- ユーザー提示の画像は「**Unity Impact FX 10 / Built-in専用 / URPへそのまま導入不可**」との注記付き。見た目・構成の**参考**にはできるが、Built-in用Shader/MaterialをそのままURP互換とみなさないこと。
- dotは着手前に**実際のローカルUnityプロジェクト、適用中のRender Pipeline Asset／Renderer、使用Shader、Bloom/HDR、Prefab構成**を調べる。GitHub上の設定と作業用ローカル環境が異なる場合は報告する。
- Unity Particle System／URP互換シェーダー／Shader Graph／簡易Mesh＋アニメーション等、**現行環境で確実に表示できる方式**を優先。新たな有料VFXアセットの購入や大規模なRender Pipeline切替はしない。
- dotとCodex・所有者が同じUnity Editor／Scene／保存データを並行操作しないこと。[作業調整ルール](WORK_COORDINATION.md)を順守し、原則として隔離した実験シーンで進める。
- **Codexは所有者の個別実行許可があるまで起動・再実行しない**。Issueに `codex-task` を勝手に付けない。

## 2. デザイン原則

### 2.1 何よりも「何が起きたか」が伝わる

接触の種類で**形・方向・持続・重量感**を変える。汎用の爆発やリングを色違いにするだけでは不十分。
- 毛・肉球への衝突：ふわっとした**面接触**。白〜淡いピンク、薄い毛埃。
- 叩き：短い芯＋押された方向への**瞬発**。
- 引っかき：爪の軌道に沿う**複数の鋭いスラッシュ**。
- 噛み：左右・上下から閉じる**挟み込み**、圧迫の時間差。
- 押し潰し：接触面に沿って横へ逃げる**強い圧力**、重量感。
- 死亡：直前の攻撃の種類が、**暗転後の赤い残像の形**で伝わる。

### 2.2 構造・時系列

各FXは必要に応じて以下の素材を組み合わせる。**すべての軽い接触に大量の粒子や5層を強制しない**。見やすさ・意味を優先する。
- **Core**：最初の1〜数フレームに見える高コントラストの芯（短く）。
- **Directional**：引っかき線、噛みの挟み込み、叩く方向など、動作の意味を示す形。
- **Wave**：接触面に沿う衝撃リング・歪み。
- **Debris**：毛埃、砂、床に合う少数の粒子。
- **Residual**：少し長く残る線、煙、赤い残像。

大きいFXは「瞬間の芯 → 広がり → 残響」の順に時間差を設ける。発生物を全て同時に拡大・縮小させるだけにしない。

### 2.3 スタイル／カメラ前提

- プレイヤーの身長は約5cm。**至近距離の猫との接触**、主観視点、カメラ近傍での見切れを想定。世界空間のパーティクルだけで満足せず、画面上での可読性を確認する。
- スクリーンショットだけでなく**動画での時間変化**を最優先で評価する。画像では見栄えしても発生・消失が弱いものは修正。
- 漫画的で読みやすい方向を基本に、現実的な血・臓器・大量の肉片等の強い残酷表現は**現段階では要求しない**。赤い衝撃線・粒子は様式的な演出。
- 白い室内・暗い場所・毛色の異なるネルコのいずれでも輪郭が消えないこと。細い線だけの場合はアウトライン・幅・輝度を調整する。
- 色は用途別に設計。暫定：軽接触は白／薄ピンク、軽打は白／淡い黄、爪は明るい冷色＋必要時だけ赤、床は茶／灰、死亡は黒＋赤。**最終色はレビューで決定**。

下表の再生時間は**編集可能な試験値**。実際のモーション速度、衝突位置、ゲーム内の時間管理と同期させて調整する。

| ID | FX名 | 主な構成・動き | 仮の持続 |
|---|---|---|---|
| NFX-01 | 軽接触／毛皮にぶつかる | 小さな面圧縮、柔らかい輪郭、毛埃数粒。大きな白フラッシュは無し | 0.15〜0.35秒 |
| NFX-02 | 猫パンチ／叩かれ | 瞬時の白いCore、短い星形アクセント、接触方向の広がり、わずかな残像 | 0.15〜0.30秒 |
| NFX-03 | 引っかかれ | 爪の軌道に沿う2〜4本程度のシャープな傷線、軌道に時間差、小粒子。爪の実際の動きに向きを合わせる | 0.20〜0.50秒 |
| NFX-04 | 噛まれ | 両側から閉じる圧迫輪郭・歯形風の短い衝撃、中央の圧縮、遅れる余韻 | 0.20〜0.50秒 |
| NFX-05 | 踏まれる／潰され | 地面と平行に広がる圧力波、押し潰された扁平な芯、床材に合う埃と重量感 | 0.25〜0.65秒 |

## 4. 死亡演出：黒画面に赤だけを残す（重点仕様）

### 4.1 狙い

激しい接触そのものを長時間見せるより、**直前のネルコの攻撃予備動作で危険が伝わる → その瞬間に視界が遮断 → 黒い画面に攻撃の象徴だけ残る**表現を試す。

**世界空間のVFXを出してから黒いUIで覆って消してしまう実装は不可。** 「黒背景」と「赤い死亡FX」は同時に独立して表示できなければならない。

### 4.2 時間軸（初期試作。秒数は確定しない）

1. **予備動作**：ネルコの攻撃姿勢・圧迫・口元の接近等。ここでは通常のゲーム画面が見えている。予備動作の長さは既存モーションと同期し、VFX側が固定しない。
2. **致死接触フレーム（t=0）**：ゲーム画面を**即時に完全な黒**へ切り替える。世界の形状・HUD・猫の体を一瞬でも透かさない。遅いフェードは使わない。
3. **赤いFXのみ（t≈0〜0.7秒）**：黒い背景の前面で赤い爪痕・噛み圧力・圧壊波などが発生・広がり・消える。タイプ別差分を試作。**白いCoreをここで長く見せない**。表示位置・線幅・粒子量は見やすさで調整。
4. **完全黒（FX消失後）**：赤い残像が完全に消え、黒背景のみの状態にする。
5. **既存の死亡復活演出へ引き渡し**：ネコルポス既存の死亡→翌朝復活／朝日トランジションを尊重。日付・保存・復活処理は書き換えず、黒画面や粒子が残留しないよう解放する。

### 4.3 レンダリング設計

- **黒背景用Full-screen UI／Overlay** と、**その上に表示する赤いVFXレイヤー**を分ける。必要ならスクリーンスペースのCanvas／専用Camera／RenderTexture等を比較し、URPで確実に動くものを選ぶ。
- 単純なParticle SystemをCamera前方に置くだけでは、死亡中のカメラ変更・NearClip・描画順の影響を受けやすい。**カメラやSceneの状態が変わっても赤いFXだけが残る**手段を採用。
- 暗転の瞬間に意図せず猫・環境・HUD・UIテキストが表示されないこと。例外的なUI表示は今後の明示仕様に従う。
- 死亡演出中にTimeScaleを0へ変更する構成の場合、**FXタイムライン／黒背景制御が停止しないよう**非スケール時間などの扱いを個別に設計する。ただし通常のゲーム内時間管理・既存死亡遷移の意味を勝手に変更しない。
- 被弾の発火は既存の死亡確定イベントと連動し、**早すぎる暗転・1フレーム遅延・重複起動**を防ぐ。
- 類似のリトライ、Scene切替、Pause、タイトル復帰、再死亡時にVFXオブジェクト・黒オーバーレイ・入力ロックが残らないよう後始末する。
- 「死亡後は朝日と色の復帰で再開する」という既存の演出方針（NEKOLPOS [Issue #68](https://github.com/kissho222/Nekolpos/issues/68) 等）を壊さない。**まず別シーンで仮演出を作り、本編統合は所有者レビュー後**にする。

### 4.4 原因別の見せ方

- **引っかき死亡**：黒背景へ斜めに走る2〜4本の赤い爪線、少し遅れて細粒子が消える。
- **噛まれ死亡**：左右／上下から閉じる赤い歯形風の輪郭・弧。接触中心が短く収縮する。
- **潰され死亡**：扁平な赤い波と、面方向へ大きく広がる圧壊リング。爆発より「重さ」を表現。
- **強打死亡（任意の追加案）**：赤いCore＋衝撃方向へ伸びる放射線。実際の死亡原因として必要になった場合のみ採用。

死因に依存しない**共通フレームワーク＋赤い差分**で制作する。キャラクターや血の塊を毎回3Dで作りこむ必要はない。

## 5. dotの制作工程

### Phase A：調査・土台（最初の仕事）

- 既存の10種を読み取り、使用しているShader/Material/Particle設定、実際の再生動画、Built-in依存箇所、ライセンスを確認。
- **URPで表示可能な独立テストシーン**を制作。元データを上書きしない。
- 世界空間VFX用Prefab（接触点に置くもの）と、**黒画面上の2D・スクリーンスペース死亡VFX**の2種類の土台を用意。
- 同一エフェクトについて「現状」「改良試作」を**同じカメラ位置・露出・再生速度**で比較できる形式を作る。

### Phase B：品質基準の見本（量産前にレビュー）

- **爪の引っかきNFX-03**を現行の画像から大幅に品質改善し、実際の動きが見えるようにする。
- そこから **引っかき死亡NFX-06** を接続し、**予備動作の仮映像 → 即時暗転 → 赤い残像 → 消失** を一連の映像で見せる。
- できれば30fps相当と60fps相当で、タイミングが破綻しないか確認。
- **この段階でレビュー停止**。OKが出るまで残り全部を同じ方法で量産しない。

### Phase C：用途別派生

- 叩き、潰し、噛み、軽接触へ設計を展開。
- 死亡原因ごとの赤い差分を作る。
- Inspectorから、色、放射方向、規模、継続時間、残留粒子数、床タイプ等を調整可能な形にする。ただし無駄な巨大設定UIは作らない。
- モーションとの同期方法（Animation Event、Timeline Signal、既存の被弾・死亡イベント等）を調べる。実際に存在しない発火APIを仮定しない。**本編接続は別途承認**。

### Phase D：見た目と負荷の検証

- **シーンの近景（身長5cm視点）と標準画面の両方**で確認。顔や手足の近さ、カメラの向き、足下での潰れ、背景の明るさに影響されないこと。
- White/Black/さまざまな毛色、朝・昼・夜・影の中、室内床の素材違いを試す。
- 大きい爆発・高密度粒子に頼らない。必要十分な粒子数、短命なオブジェクト、共有マテリアル、Prefab再利用で処理負荷を抑える。
- 同時多重発火／短時間連打／Pause／Scene退出／早期死亡／復活をテスト。
- Unity Editor実行・PCビルド・WebGL等、**実際に確認できた対象と未検証対象を区別**する。最終的な性能目標は対象プラットフォームと現行ゲーム負荷に基づいて提案する。

## 6. 絶対に避けること

- Built-in用マテリアルをURP対応済みと偽る、またはUnity全体のレンダーパイプラインを勝手に変更する。
- 「10種の色を塗り替えただけ」「輪っかを大量に重ねた」だけの完成扱い。
- 本編の死亡・復活シーケンス、セーブデータ、Timeline、Sceneを無断改変する。
- 死亡時に黒背景が赤いVFXを覆って見えなくなる構成。
- 動画の品質チェックなしに静止画像だけで完成を宣言する。
- 視界を大きく塞ぐ常時フラッシュ、極端な強光、画面振動をデフォルトにする。アクセシビリティ上の調整余地を残す。
- 勝手に血みどろのゴア表現や新規の死亡ルート・台詞を追加する。
- dotの検証環境整備が目的化し、実際に見える試作品が長期間出てこない状態。

## 7. 納品物と受入チェック

### 必須成果物
1. **URP互換のVFXアセット／Prefab（または再利用可能なUnityデータ）**。少なくとも最初は引っかきと引っかき死亡の2点。
2. **独立した実験シーン**：背景・ネルコの仮形状・攻撃接触を代用した動作確認ができる。既存本編Sceneを勝手に更新しない。
3. **比較用動画**：従来10種の原型から何が改善されたか、30/60fpsで再生して分かるもの。静止画のみの場合は未達。
4. **黒背景死亡シーケンスの短いデモ**。黒の後も赤FXが表示され、その後に完全消失すること。
5. **再利用と発火方法の説明**：World SpaceとScreen Space、設定値、Prefab、実際の使い方。
6. **計測・制約レポート**：利用したUnity/URPのバージョン、表示確認、推奨同時数、未実施のテスト、外部アセットのライセンス。
7. オーナーのレビューを受けてから、残る種類の量産と本編への統合作業を決定する。

### 受入チェックリスト

- [ ] Built-in専用の原型から脱し、**現在のURP環境で動いている**。
- [ ] アクション種別（叩き・噛み・爪・潰れ）が、**見た目と動きの違い**で識別できる。
- [ ] 当たりの瞬間→広がり→余韻の演出にメリハリがある。
- [ ] 主観視点・5cmプレイヤー・明暗／異なる毛色背景でも見やすい。
- [ ] 死亡の致死フレームに**即時の完全暗転**が入り、**黒画面の上に赤FXだけ**が見える。
- [ ] 赤FXは確実に消失し、既存の日付更新・復活シーケンスの後処理を壊さない見込みが説明されている。
- [ ] 低負荷に配慮し、実測と未測定を区別している。
- [ ] 最初の完成見本をユーザーに提示し、**量産前にレビューを受けた**。
- [ ] Codex自律実行・本編Sceneへの無許可変更は行っていない。
