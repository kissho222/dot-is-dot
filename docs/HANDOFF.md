## 1. この文書の目的

所有者は、ChatGPT Proとdotを約1か月集中的に利用し、ゲーム制作・3Dモデリング・調査・資料整理・Codexへの指示・プロジェクト進捗管理を委任したい。

この文書はChatGPTでの過去の議論を要約した初期コンテキストである。dotが過去の会話を網羅的に読めることを前提にしない。**最新のゲームリポジトリや資料と食い違う場合は、状況を照合して報告すること。**

### 確実に決まっていることと未決事項を分ける

- **決定済み**：当人が明示した方針、日程、担当体制、既存運用。
- **作業候補**：検討・試作・調査をしてみたい項目。実装済み、不要になった可能性がある。
- **仕様未確定**：細かい制作仕様、配布方法、作業手順などは勝手に決めない。

本資料の作成時点でProへの加入完了やdotへの実作業依頼完了は確認していない。

## 3. NEKOLPOS（ネコルポス）

### 作品概要・技術背景

- 身長約5cmのプレイヤーが巨大な猫と交流するゲーム。生活空間の小物もプレイヤー視点では非常に大きい。
- 主な開発環境はUnity 2022.3.62f3 LTS、TextMeshPro、DOTween。WebGL向けの実装・既存運用がある。現在の環境・ブランチ・実装状況は実物を確認する。
- 会話・心理状態・時間帯・日記・猫の動作が関係する。既存仕様やコードを理解せずに改変しない。
- 目標日程：2027-02-22 Steam Nextフェス参加、2027-03-03 早期アクセス販売開始、2028-02-22 完成版販売。Nextフェス参加の是非は再議論しない。
- Steam紹介用の動画はまだなく、「言葉を教えるモード」とデバッグモードが落ち着いた後、SEを付けて撮影する方針。

### 3D小物・家具制作：高優先

まず依頼したい制作対象：
- 自動給餌器
- 自動給水器
- 猫用トイレ
- 餌皿・水皿、周辺の生活小物

余力があれば：
- ロボット掃除機（ルンバ風）と充電ドック
- 爪とぎ跡のある家具、傷んだ壁・ソファ・棚など
- 猫用品・室内装飾の追加
- 家具・小物を配置した部屋の一角
- さらに余力があればワンルーム全体

**重要**：NEKOLPOSのほぼすべての3D小物は小人視点で至近距離まで接近でき、極端なハイポリ化なしに近くでも破綻しない形状と、自然な経年使用感を要する。自動給餌器・給水器・全自動猫トイレは個別の具体的な注文が提示済みであり、[3D_ASSET_SPECS.md](3D_ASSET_SPECS.md) を正本として参照する。給餌器は白い電動式、餌残量を下げて見せるメッシュ、実際に侵入できる給餌口の横穴、一部の個別カリカリが必須。給水器は白い水道直結電動式、常時流れて見える水の簡易表現、小人の登攀・入水を想定した構造が必須。全自動猫トイレは**白いドーム型・固定ベースと回転体を分割、通常時から参考画像の回転姿勢に移行できる構造、猫が入れる内部空間、粗い猫砂、正面右下の可動スイッチ**が必須。**まず外観と将来拡張可能な構造を制作し、給餌や泳ぎ、清掃のゲーム機能は未実装**。元の参考画像は計4枚（給餌器・給水器2枚＋猫トイレ2枚）あり、公開GitHubには載せていないため、dotへ別途共有すること。

デザイン完成画像だけでなく、**編集可能な制作データとUnityへ取り込める実物の成果物**を目指す。制作は段階的に行い、1点目の検証結果を後続へ再利用する。

### 本体・演出の作業候補（未完了とは限らない）

- 言葉を教えるモード、デバッグモードの完成・検証。
- 心理値6種（Affection / Sadistic / Concern / Hostility / Obedience / Instinct）と挙動の連携、従順関連の検証。
- 日記、会話、時間経過イベント、Yarn連携の整備。
- ネルコの移動、追従、視線、瞬き、瞳孔、行動表現の整備。
- カメラ、時間帯・天候Lighting、朝昼夕夜の共通トランジション、タブレット発光などの演出。
- 既存の2Dアニメーション素材の適用とレビュー。
- 猫パンチ等の未完成モーションを無理に作るより、当面は対応会話を拒否会話にする方針。
- Dust Specs VFXは後回し。以前は2027年1月頃に再検討する判断。
- Steamストアページと告知素材の準備。公開時期・演出との依存関係を尊重する。

### 開発自動化：長期的価値が高い

特に強い関心がある：
- 任意のゲーム場面へジャンプできるデバッグ機能。
- 時間、心理値、会話状態、イベントを操作する検証ツール。
- Unity Editorでの自動テスト・ログ収集・不具合再現。
- Codexによる実装→テスト→修正・レビューの円滑化。
- GitHub Issueの確認、分割、進捗整備。

dotが本当にUnity Editor/Blender/ローカルファイルを操作できるかは、接続環境・権限・稼働条件を確認すること。アクセスできない工程については未検証と明記し、実行できたかのように報告しない。同じUnityプロジェクトの同時編集・破壊的変更を避ける。

## 4. Warrior Cats: Clans of the Forest 日本語化

### 確定事項

- 2026-10-24（日本時間）の発売予定に合わせて、発売後の日本語化可否・難易度・必要作業の調査を集中的に行いたい。
- **翻訳に自信のあるメンバー3人、アシスト3人**が参加予定。所有者がチーム全体を取りまとめ、仕事の割り振りを行う。
- チーム連絡用Discordはすでに準備済み。
- 翻訳管理用Googleスプレッドシートは後日作成予定。**既に存在すると仮定しない。**
- まず技術面の成立性を調べ、人間の翻訳作業を効率的に配分する。

### 発売後にdotへ依頼したい調査

1. 正当に利用できるインストール済みファイルを調査し、エンジン・データ構成・言語データ形式を確認。
2. テキストの抽出方法、再投入方法、差分適用方法、アップデート耐性を検討。
3. 日本語フォント、UIレイアウト、改行、変数、代名詞、性別表現、表示上限の対応可否を検証。
4. 少数サンプルの翻訳をゲーム上に反映し、技術的に成立するか試験。成功／失敗／未確認を明記。
5. 翻訳対象の総量・種類・難易度・文脈不足箇所を集計。
6. 用語辞書、翻訳管理台帳、レビュー・差し戻し・QAの流れを設計。
7. 翻訳担当3名・アシスト3名へ割り当てる仕事を、実際のデータ量と各人の適性に基づいて提案。
8. 開発元の方針、利用規約、配布可能な成果物の範囲を確認。

**翻訳役のA/B/Cなどの固定割当はまだ決めない。** 役割分担は技術調査・仕事量判明後に提案する。翻訳者にGitHubの利用を強制しない。基本はDiscord連絡＋スプレッドシート上の翻訳作業、技術作業はGitHubを利用する構成を想定。

第三者ゲームの著作物・原文データを公開リポジトリへ格納しない。DRMやアクセス制御を回避しない。再配布できるデータの範囲は確認すること。

## 5. その他のゲーム制作・試作

すべて「既存案から小さい動作検証を作る」候補であり、未確認の新仕様を勝手に正式決定しない。

- **『ユアパークへようこそ！』**：配信者・VTuber向け。カメラ、マイク、アバター、配信コメントなどを使うミニゲームからメタホラーへ。Webカメラ・VTube Studio・マイク連携の技術検証、頭を振る音ゲー、ピアノ音程当て、弾幕回避などの縦切り試作。年内の仮制作に関心が強い。
- **『ぐにゃぐにゃ怪盗』**：一本道高速走行、スロー中の回避入力、通常速度再生。博物館侵入チュートリアルが試作候補。
- **『トローグライト』**：行動に癖のある仲間が登場するローグライト。酒場での選抜、指示と自律行動の差別化、戦闘試作。
- **『ゆっくりにはなりたくない！』**：コイン／運搬・スペル・妨害を組み合わせたゲーム。Steam Workshopによる拡張案もある。
- **『アドセンスウォーズ』**：無課金対戦の広告ギミック。架空広告、広告地雷、フラッシュ、床広告など。ネットワークや運営面は高難度。
- **『これがバックギャモンだ！』**：変則ルール生成。ルール説明、共有、人気ルールランキングなど完成版構想。
- **『勇者よ！あの生成AIイラストのドラゴンを倒してきてくれ！』**：ドラゴン素材の差分・軽アニメ、RPG制作と会話原稿。
- **ジャパまんクリッカー**：既存実装の最適化・調整など、必要に応じて調査。

## 7. 既存の開発・資料管理方針

- 仕様・設計意図・将来構想は永続的なドキュメントへ、作業指示と完了判定はIssueへ分ける。
- Codex指示はGitHubの対象リポジトリでIssueを作成し、**codex-task** ラベルを必ず付与する。
- dot-is-dotは複数プロジェクトの調整役。各ゲームのソースや確定仕様をこのリポジトリに複製して正本扱いしない。
- IssueやPRの状態は都度確認する。過去会話に「未実装」とあっても既に完成している可能性がある。
- 移動、削除、公開、重要なマージ、支出、対外連絡等は所有者の承認を要する。
- 成果物には、何を作ったか、どこにあるか、検証結果、未検証の点、次に必要な判断を残す。
