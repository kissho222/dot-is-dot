# 『ぐにゃぐにゃ怪盗』初期怪盗衣装・BoZo変形適合検証（v0.1）

## 位置づけ

**dotへの実制作依頼**。単なるキャラクターイラストではなく、後でUnityのゲームに持ち込める編集可能な**3D衣装と変形に耐える構造**を目指す。正式なゲーム本体の制作・回避操作・当たり判定・完成リグの実装とは分けて扱う。

### 既にわかっている環境

- 素体候補：**BoZo: Stylized Modular Characters**。
- ユーザーから、**NEKOLPOSのローカル作業フォルダ内にBoZoをインポート済み**との申告がある。
- dotは**そのローカル作業フォルダへアクセスできるか最初に確かめること**。GitHubにアセット本体があるとは推定しない。接続できなければ、必要なアクセス方法を報告する。
- BoZoのリグ、BlendShape、SkinnedMeshRenderer、骨の構成、ライセンス範囲、インポート設定は**未検証**。まず現物を調べること。
- NEKOLPOSの資産を『ぐにゃぐにゃ怪盗』に使うのは**作業用コピー**で行う。NEKOLPOSのシーン・既存BoZoプレハブ・既存素材を破壊・上書きしない。完成品は可能なら怪盗用に独立した作業フォルダ／Unityプロジェクトに置く。
- BoZo本体など、第三者の有料素材・ライセンス対象ファイルを**公開リポジトリ（dot-is-dot）へコピーしない**。利用・派生・再配布条件を確認する。GitHubには制作仕様・進捗・許可された自作部分だけを記録。

## デザインの確定方針

1. **初回起動・PV・スクリーンショットで、見ただけで怪盗と認識できるベタな服装**を初期衣装にする。
2. 人型のスタイリッシュな怪盗。黒／白を基調に、仮の差し色を少量。
3. アイマスク、白手袋、フォーマル風ジャケット／スーツ、細身のパンツ、靴、短いケープまたは燕尾などの**怪盗の記号**をラフで検証。帽子・襟・ケープ等は変形と画面の見やすさを考慮し、最終デザインはレビューで決める。
4. **衣装ごとに「ぐにゃぐにゃ度」（変形許容範囲や曲がり方）を変えられる**拡張を予定する。初期衣装はゴムのように大きく伸び縮み・屈曲する方向。
5. 他のデザイン案は衣装変更・装備変更時に活用可能。**今は初期衣装を1着だけ**作る。
6. 見た目の美しさより優先するのは、**極端に変形しても服・素体の表示が破綻しないこと**。これを満たさない完成静止画だけの納品は不可。

## 既に決まっているゲーム挙動（今回の衣装・変形テストに必須）

- 主人公は一本道を**常に前方へ等速で走り続ける**。ポーズを変形させても走行アニメーションを停止・リセットしない。
- 体を気持ちよくぐにゃぐにゃに曲げる・伸ばす・潰すことができる。
- **操作中も身体が元の走行姿勢へ戻ろうとする**。操作を解除すると規定の復元過程で戻る。
- **復元に要するゲーム内の時間は一定**。衣装による「ぐにゃぐにゃ度」はまず変形範囲・変形形態で表現し、**復元時間を衣装ごとに変えない**（以前の案で復元速度を衣装パラメータに入れたが、後の確定指示を優先）。
- スローモーションでは**ゲーム内時間そのものが遅くなる**ので、復元・走行・変形・ジャンプも同じ時間軸で進める。復元だけ実時間／unscaled時間で走らせない。
- **両足を操作で上へ持ち上げるとジャンプ扱い**とする。前方の等速移動は継続し、空中でも走行モーションを維持する。
- クリア後、プレイ中の変形を**通常速度でずれなく再生**する設計を想定。非決定的な布物理の結果をリプレイの必須構成にしない。必要に応じて骨・頂点状態を記録／再生する方式を提案する。

**注記**：これはゲームメカニクスの制作タスクではなく、衣装と変形適合テストの前提条件。ゲーム側への実装は別Issueに分ける。

## dotに求める作業工程

### Phase 0 — BoZo現物の調査（必須）

- ローカルNEKOLPOS作業フォルダでBoZoの素体Prefab、モデル、スケルトン、Animator、Mesh、BlendShape、マテリアル等の所在を特定。
- BoZoの**モジュール衣装方式・既存リグを流用できる範囲**を確認。極端な伸縮でBoZo本体が破綻する場合は、その事実を先に報告する。
- 衣装の追従方法を比較：共通スケルトン＋ウェイト／専用補助骨／BlendShape／変形シェーダー／独立パーツを追従させる方式等。選定理由と限界を示す。
- 版権上の扱いと、安全な作業コピー先を確認する。ソースアセット自体を公開repoに出さない。

### Phase 1 — 初期デザインラフと素体へのフィット

- BoZoの人間体型に合う**正統派怪盗衣装を1案**作成。アイマスク、手袋、スーツ、足元などを揃える。
- 装飾はシルエット優先、過剰な硬質パーツや長いマントを避ける。ケープ／燕尾は変形との相性を検証して採用を判断。
- **正面・側面・背面の立ち姿、走行中の見え方**を提示してレビューを受ける。
- 素体の骨／マテリアル／衣装メッシュと、重なって見える体の部分をどう扱うか検討する。着衣部分の身体メッシュ非表示なども比較対象。

### Phase 2 — 変形破綻テスト（最重要）

通常走行に変形を重ね、少なくとも以下を試す：

1. 胴体の極端な左右屈曲。
2. 背中を大きく反らす。
3. 身体の上下圧縮（ぺちゃんこ）。
4. 胴体・腕・脚の大きな引き伸ばし。
5. 上半身の大きなねじれ。
6. 両足を上げたジャンプ姿勢。
7. 複数の変形を組み合わせた極端なポーズ。
8. 変形から走行姿勢への自動復元中。

**チェック箇所**：肩・脇・股・腰・肘・膝・首、ケープの根元、手袋・靴との境界。衣装の裂け、素体貫通、法線反転、UVの不自然な伸長、メッシュ崩壊、パーツ分離、装飾の異常挙動を観察する。

**操作入力・復元時間はまだ本実装不要**。まず変形テスト用の骨操作・簡単なデモで十分。ただし走行ベースと変形を重ねる構成を意識する。

### Phase 3 — 修正と納品

- 破綻が出た箇所を修正し、初期衣装と再利用できるウェイト・補助骨・変形テスト手順を用意。
- **BoZoが極端な伸縮に耐えない場合は無理な完成宣言をせず、骨構造の拡張／専用の変形可能素体／衣装の追従方式変更などを比較し、判断を仰ぐ**。
- 編集可能な元データ、Unityで使えるモデル、マテリアル、シーンまたは検証スクリプト、スクリーンショット／短い動画（可能なら）を、適切な非公開作業先に置く。
- Unityで実機確認をしていない場合、その旨を明記する。

## 受入条件

- [ ] BoZo素体のリグ・モジュール構造・作業上の制約が報告されている。
- [ ] 初見で怪盗とわかる、BoZoにフィットした衣装ラフがある。
- [ ] 6種類以上の極端な変形姿勢と、走行・復元の重ね合わせをテストし、破綻状況が見える。
- [ ] 問題のあるメッシュ・部位の修正状況／残課題を列挙できる。
- [ ] 衣装を差し替えても再利用できるパイプライン案がある。
- [ ] 元データや実装可能な成果物の保存先、テスト環境、未検証事項が報告されている。
- [ ] 完成と判断する前に**所有者のラフ・動作レビュー**を受ける。

## この段階で作らないもの

- ステージ、敵、レーザー、盗品、多数の別衣装。
- ゲーム全体の走行・ジャンプ・スロー・リプレイ・衝突システム。
- BoZoアセットの公開再配布、既存NEKOLPOSシーンの破壊的変更。
