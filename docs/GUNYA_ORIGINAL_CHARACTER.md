# ぐにゃぐにゃ怪盗：新規オリジナル変形素体・怪盗衣装（v1.0）

## 背景・変更理由
従来 [Issue #11](https://github.com/kissho222/dot-is-dot/issues/11) では「BoZo: Stylized Modular Characters」をベースに衣装制作する計画だった。しかしAIによるアセット利用の明示的な承認が確認できなかったという報告を受け、**BoZoそのものとその派生メッシュ・リグ・テクスチャに依存しない、独立したオリジナル素体の新規制作へ切り替える。** 見た目の一般的な怪盗記号（アイマスク等）を参考にすることは可。BoZoからの複製、トレース、メッシュの変形・流用等は行わない。

## 確定したゲーム・デザイン方針
- **人型のスタイリッシュな怪盗**。初回起動・PV・スクショだけで「怪盗」とわかる典型的な衣装を初期装備とする。
- 細身のフォーマル風衣装、アイマスク、手袋、ブーツ／革靴、燕尾や短いケープ等を候補とする。黒白を基調に差し色は少量。帽子などの細部はラフレビューで決定。
- **初期衣装でも身体をゴムのように異常な程度まで伸長・圧縮・屈曲・ねじり可能**。後の別装備に応じて変形可能範囲・形態を変えられる設計。
- どんな変形ポーズでも基本の**走行アニメーションは止めない**。コース上の前進速度は常時一定（スロー中はゲーム内時間自体を遅くする）。
- プレイヤーによる変形中にも**復元しようとする力が継続**。手を離すと走行の基準姿勢に復帰する。**復元のゲーム内時間は一定**とし、スローでは実時間側が伸びる。通常速度リプレイとの時間的整合を壊さない。
- **両足をプレイヤー操作で持ち上げるとジャンプとみなす**。ジャンプ中も水平前進および走行サイクルを止めない。
- レーザー等の障害物を回避する通常速度再生で、驚異的な身体操作に見えることが目標。表現のための見た目・リグ検証と、ゲーム本編システム開発は分ける。

## 第一段階の実制作
1. 完全新規制作の**灰色の簡素な人型素体1体**。まず外見ではなく変形方式を確認する。
2. 骨（追加ボーン、伸縮可能な階層、補助骨）、ウェイト、必要ならBlendShape／補正形状・シェーダーなどで極端な変形に耐える設計。
3. 少なくとも「左右屈曲・強い反り・身体の圧縮・腕脚と胴の伸長・ねじり・両脚を上げる姿勢・複合変形・走行状態からの復元」を試す。
4. **素体変形が成立してから**、怪盗衣装ラフ1着を制作。上着・ズボンは身体密着の一体材質／近接メッシュなど複数案から選べる。衣装を硬い外殻として作り、変形時に貫通させない。
5. 正面・背面・側面・走行・極端変形のプレビューを提出し、所有者のレビューを得る。
6. Blender元データとUnityへ取り込める形式を用意し、実際に確認できた範囲を記録。後の衣装バリエーションへ再利用できる設計を残す。

## 技術的な注意
- 既存のNEKOLPOSのローカルフォルダにBoZoが存在しても、**今回の制作素材として読み込まない**。参照せず独立した新規Blender作業ファイルから開始。
- 制作上のデフォルメ・身長・色・装飾などはラフで提案し、過剰な仕様の先決めは避ける。
- 極端な姿勢で法線・UV・メッシュ交差・関節部の厚みを確認する。標準Humanoidの制限では実現できない場合は専用リグを優先。
- **まずは独立したテスト環境で制作する**。既存NEKOLPOSのScene、Prefab、Unity Editorや通常セーブデータを占有・上書きしない。
- このIssue群は**dotの3D・アセット制作担当**。Codexは所有者の個別実行許可がない限り起動しない。Issueの作成だけで `codex-task` ラベルを付けない。
- BoZoのライセンス上の利用可否について「禁止確定」とは断定しない。承認確認まで制作には使わない、という実務上の判断である。

## 納品判定
- 見た目だけでなく、変形テストの証拠があること。
- 変形可能素体の単体モデルと衣装1着が個別に確認できること。
- テストに失敗した場合は失敗箇所と代替構造の提案を報告し、完成と偽らない。
- ステージ・障害物・敵・AI・ゲーム制御は別タスク。
